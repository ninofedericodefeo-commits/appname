# Local bank PDF and CSV import

In Account, tap **Import statement**, use **Import** in Transactions, or use **Import bank PDF or CSV** in Subs. Choose a Citizens checking/savings statement PDF, a transaction CSV exported by any bank, or paste CSV contents. The source file is read locally, its cache copy is removed when possible, and PDF/CSV contents are never retained in saved app state or uploaded to a service. System handoff/cache copies are removed after reading when possible.

## Citizens checking/savings PDFs

Download the original statement from Citizens online banking’s Document Center, then open it in GasFinder from the PDF’s Share menu, or choose it from Files. The initial importer supports text PDFs with an identifiable full statement period and dated **Deposits & Credits**, **Withdrawals & Debits**, **Other withdrawals**, or equivalent supported deposit/withdrawal sections. It handles ATM/debit-card withdrawals, electronic withdrawals, headings with counts/totals, explicit withdrawal/deposit columns, transaction amounts before/after descriptions, wrapped descriptions and continuation pages. Review shows spending/credit counts per page so missing spending is visible. Unrecognized dated tables produce warnings rather than silently carrying a previous summary section. Short transaction dates get their year from the statement period, including year boundaries.

- Up to 10 MB, 40 pages, 5,000 transactions and 2 million extracted characters. Reading can be canceled; a 45-second timeout offers a smaller-file retry.
- PDF.js and its processing engine are bundled with the app. A local Expo DOM component extracts positioned text in a WebView on native and directly in the browser on web. No bank statement is uploaded, and no CDN worker, OCR service or bank login is used.
- Review each date, description and amount against the original PDF. Rows identify PDF page and extracted line (not a printed transaction number). Unreadable or ambiguous transaction rows are reported; they are never guessed.
- Identified credits/refunds, transfers, card-balance payments, ATM cash withdrawals and fees are excluded from purchases. Checks, fee-only sections, account summaries and running balances are not imported. Other transfer descriptions may still need manual deselection. The separate Account bank history retains readable movements from supported tables, including deposits, transfers, card payments and fees. A clearly labeled ending/closing/new balance is separately reviewed for updating Account; running balances are excluded.
- Unsupported banks (including First Citizens), Citizens credit cards, explicit non-USD currency, multiple identifiable accounts in one PDF, password-protected PDFs, scans/photos and unsupported table layouts show an error. Download separate statements for each account. CSV remains available for unsupported PDFs; there is no OCR yet.
- The original PDF and positioned text are discarded after extraction, cancellation or leaving the screen. App storage retains confirmed purchase records and, when enabled, signed bank transactions with date/title/status, local source metadata/account nickname, purchase links and deduplication identities. A confirmed closing balance is retained with its statement date and import identity, without the original PDF.

The initial PDF layouts are covered by **synthetic** fixtures. A redacted real Citizens checking/savings statement has not been provided; the reported page 2 issue is covered with representative withdrawal-heading/column regressions, not the actual file; verify that exact layout on a physical phone before relying on its purchase history.

## Citizens PDF handoff

After rebuilding the app, **Share → GasFinder / Open in GasFinder** on a downloaded PDF opens `/bank-import` and starts reading it automatically. Final import still shows the transaction and balance review. The free Apple Personal Team build registers PDF/CSV document types without App Groups; iOS supplies an Inbox copy, which is removed after reading. Android accepts single PDF/CSV share intents. An enrolled-team build also enables Expo’s iOS share extension for files. Existing Maps text/link sharing still opens Gas on your drive.

File URIs and financial file names stay in a short-lived in-memory handoff; only an opaque token appears in navigation. Only local file/content URIs are read, with the same size limits. A temporary cache copy is removed in `finally`. The source document outside the app’s own Inbox is not deleted. Enrolled-team iOS sharing creates an App Group copy; only files received through that extension inside an app-owned shared container are cleaned up. Expired or unreadable handoffs offer the ordinary file picker.

Citizens still requires authentication and a statement download. No bank login, undocumented bank API or unattended retrieval is implemented. Direct PDF opening removes the extra file-picking step, so a separate Shortcut is unnecessary for this flow. The in-app **Get statements from Citizens** guide explains download/share and Save to Files fallback. Verify the native handoff on the new phone build; browser tests cannot prove system document routing.

## Review

- Give the account a nickname and keep it consistent on later imports. The last successful nickname is remembered. It scopes import identities across accounts.
- Common date/description/amount or debit/credit headings are detected. Tap column fields to correct them. More columns exposes currency, transaction type, status and transaction ID.
- Check whether money spent is positive or negative. Choose month/day or day/month for slash dates; ISO calendar dates are also supported. Dates need a four-digit year. Invalid/future dates and invalid amounts are shown among skipped rows.
- CSV supports quoted commas, escaped quotes, embedded newlines, UTF-8 BOM, CRLF, tab and semicolon separators. Limits: 2 MB and 5,000 transaction rows. Other-bank PDF/XLSX statements still need a CSV export.
- Known credits/refunds/transfers/payments and pending entries are excluded from savings purchases. Zero amounts and non-USD rows are excluded from both purchases and bank history. Different banks label transfers differently: review selections and deselect internal transfers or card-balance payments before importing. The app cannot infer all transaction categories.
- New spending rows start selected. Possible matches to existing Apple Pay, manual or bank entries start unchecked and identify the matching entry. Matching uses equal amounts and merchant text within three calendar days to allow posting delays; a same-day amount alone is flagged for review. Matching is one-to-one: one app entry can explain only one statement row. Merchant matches get priority over unrelated same-price logs. Confirmed matches retain the app purchase’s savings contribution, store the bank identity/description/date and link the account row to it. Subscription evidence can use the matched bank description/date. Include a possible match only if it is a different purchase. Already imported identities cannot be selected again.

## Account transaction history

**Save bank history to Account** starts enabled and is shown explicitly before confirmation. **Review bank history** shows signed amounts, dates, source rows and supplied posting status. This includes readable deposits, transfers, fees and pending transactions that are excluded from savings purchases. Turn it off to import only selected purchases. An old statement can fill the new ledger even when all its purchases were previously imported.

The account ledger has its own identities and links to imported or matched manual/Apple Pay purchases so the same charge appears once in Account. If a possible match is explicitly selected as a different purchase, both remain visible. Original purchases remain available in the unified transaction timeline and continue feeding subscription suggestions. Bank movements excluded from purchases never feed savings rules or subscriptions.

Citizens statement rows are posted; CSV rows use supplied pending/posted status, or **Imported** when status was not supplied. A savings suggestion awaiting review is not a pending bank charge. If a bank transaction ID is available, a later posted export updates a pending row; older pending data cannot downgrade posted status. Without bank IDs, changed descriptions/dates/amounts may create a distinct row.

Account displays the newest seven transactions, including standalone savings adjustments. Purchase contributions appear inside their purchase detail rather than as a second row. Tap a purchase for the former Activity editing/deletion and savings-review controls; **Log a purchase** is available below the heading. **See all** opens a virtualized list with search and money-in/money-out/pending/savings filters. Internal savings adjustments are excluded from bank money-in/money-out filters. Prior purchase imports remain visible after the version 6 migration. Reimport the original statement once to add its other readable account movements. No source file, account number or running balance is retained. Account history does not decrement the saved bank balance.

## Balance and savings

The default is history only, with no savings contribution. Account’s main amount is the saved bank balance minus money set aside; the actual balance is smaller and masked until revealed. A clear Citizens closing balance defaults to updating Account on confirmation. It is labeled with the statement closing date; later activity may have changed the real bank balance. A newer saved balance makes older statement balances unchecked, with explicit opt-in to replace it. A balance already applied from the same statement cannot roll back a later manual update on reimport. A PDF can update just the balance even when all transactions are already saved. Missing or conflicting closing balances require manual entry. **Apply my goal’s rule** is optional, with the exact capped set-aside change shown before confirmation. A confirmed import applies the current rule oldest first, capped by the active goal remainder and available balance after the reviewed statement update. It sets only a clearly labeled, confirmed statement closing balance, never subtracts imported spending again, converts currencies, moves money or releases earlier savings because of a refund.

Actual purchase dates are preserved, so imports contribute to the existing 30-day spending history. Imported entries say **Citizens PDF** or **Bank CSV** in transaction details. Editing or deleting one follows normal purchase behavior: an earlier set-aside remains until lowered explicitly in Edit goal.

Import IDs use the account nickname and the bank transaction ID when available. Without IDs they use date, amount, normalized description and the occurrence number of an identical row. Repeat/overlapping exports are deduplicated. Keys remain after deleting a purchase to avoid reserving again on reimport. Changed bank descriptions or incomplete exports of repeated identical transactions can be ambiguous; possible-match review is deliberately conservative.

## Subscription suggestions

Confirmed bank imports feed **Subs → From bank history** automatically, including existing bank CSV purchases. Monthly (25–37 day intervals) and yearly (350–380 day intervals) repeated charges with similar prices produce suggestions. The latest six charges provide visible date/amount evidence; recent monthly charges must be within 65 days and annual charges within 400 days. Very different prices and frequent/irregular charges do not qualify. A single known subscription provider or explicitly recurring charge is labeled **Possible subscription**; one charge cannot establish a billing cadence.

**Review & add** prefills an editable name, latest charge, cadence and renewal day/month. Posting dates and prices are estimates; confirm them with the provider. Only **Add subscription** creates a subscription. Dismissals persist and can be restored. Existing subscriptions, including renamed imported ones and entries marked canceled, are not suggested again. Suggestions do not alter savings or enable reminders. Generic Amazon purchases and ambiguous Apple bill descriptions are not treated as known subscriptions.

## Development build

`expo-document-picker` is an SDK-compatible native dependency. Rebuild the phone app with `npm run ios -- --device` (or the Android equivalent) to enable file selection and PDF opening. The npm command runs Expo Prebuild first so native document registration is refreshed even when an ignored `ios/` directory already exists. `npx expo run:ios` alone skips that step for an existing native project. Loading the picker is deferred so older development builds can open the screen and use **Or paste CSV**. PDF extraction adds a JavaScript dependency only and reuses the existing WebView; PDF handoff also needs the native document registration. No iCloud storage, App Group, push or bank API capability is added.

### Shortcuts says GasFinder isn’t installed or cannot open the file

An older GasFinder native build can have the correct bundle identifier (`com.anonymous.gasfinder`) and URL scheme but lack `CFBundleDocumentTypes`. Metro refreshes cannot register it as a PDF-opening app. Generate and install the updated build with `npm run ios -- --device`, open GasFinder once, then retry the existing shortcut. Updating the same app preserves its local data; do not uninstall it to fix registration.

For a running Metro server on 8081, use `npm run ios -- --device <device-UDID> --no-bundler`. Expo CLI does not allow combining `--port` with `--no-bundler`. Verify the generated and compiled app’s Info.plist declares `com.adobe.pdf`, `public.comma-separated-values-text`, and `LSSupportsOpeningDocumentsInPlace = false`.
