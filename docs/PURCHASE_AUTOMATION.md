# Local purchase automation

Goals now have a fixed-dollar, percentage, or round-up rule chosen during setup and editable later. Each purchase logged manually or received from an iPhone Shortcut applies that rule to the **estimated pocket**, capped by the remaining goal and any available balance the user entered. If the rule would set aside nothing or the cap is exhausted, the purchase remains pending for a manual decision. No money is transferred, and the manually entered bank balance is not updated by a purchase.

For an iPhone Apple Pay card tap, use Shortcuts > Automation > Transaction, select the card, and choose Run Immediately. Build a URL action beginning `gasfinder://import-purchase?amount=` followed by the transaction's Amount magic variable. Append `&merchant=` followed by a URL-encoded Merchant magic variable. Add an Open URLs action to open that URL. The optional `&id=` parameter can carry a stable transaction identifier to prevent duplicate imports; without it, repeated links for the same merchant and amount within one minute are treated as one purchase. Test a real supported tap after setup. The app rejects an empty merchant and zero or invalid USD amount.

Apple’s Transaction automation covers the selected card being tapped with the iPhone. It does not provide every card, online, or cash purchase. For full automatic account transaction history, a separate user-authorized provider or an eligible FinanceKit integration would be required; neither is configured in this local build. Do not describe this Shortcut as full transaction syncing.

Expo development builds do not cold-launch from an app-specific link. Open the development build before testing the Shortcut, or use a standalone installed build for a reliable closed-app launch. The custom `gasfinder` scheme is already in `app.json`; test with `npx uri-scheme open 'gasfinder://import-purchase?amount=4.25&merchant=Test%20purchase' --ios` on an installed build, knowing that this test link will log a local purchase.
