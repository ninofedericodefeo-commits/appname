## Product decisions

- One user for now. Personal data remains local; no bank/card connection, account synchronization, real money transfers, custody, stock purchases or brokerage integration. Set-aside values are estimates of money still in the user's account. USD only.
- Four bottom tabs, with stable tab transitions: Gas; Goals with past goals; Account; Subs with Spending Pause on the same page. No More tab or separate embedded subpages.
- Style: cream paper, dark green, restrained rust/lime accents, simple mobile layouts, readable values and familiar icon actions. Avoid numbered dashboard sections and verbose goal copy.

## Implemented features

- Gas defaults to map, with a list alternative. GPS starts nearby OpenStreetMap station discovery on launch; stations render progressively. No paid map key is required. Missing names say Name not listed; missing prices say No price yet and map markers say Gas. The sample-data banner and lowest-price hero are removed. Report a price and Gas on your drive sit below the map. MapLibre GL JS 6.13.0 renders OpenFreeMap Positron vector maps with attribution, modern price pills, zoom controls, a location dot and recentering. Public map hosting is free with no account/key; the pinned module worker loads from UNPKG. Internet and WebGL are required.
- Gas receipt reports and direct price reports belong to Gas. Local reports link prices and their history graph to locations. GPS can supply approximate place details; maps open the station's actual coordinates.
- Gas on your drive takes a destination entered/shared/pasted into the app, estimates fuel needs with saved car profiles, MPG/tank capacity, and fuel amount or percentage. It plans multiple refills for long trips. A saved refill threshold and Apple/Google Maps preference control planning and route handoff. The app cannot read another map app's current destination silently. Service failures have fallback/retry handling, not fake successful plans.
- Savings supports one active goal, optional calendar deadline, fixed/percent/round-up rule, editable limits, all-or-none starting savings assignment, goal editing/deletion, archives, release/lower-savings inside Edit goal, and manual set-aside/purchase forms inside Edit goal. Existing simulated investing records stay read-only and never count as savings. Editing/deleting a purchase does not release its set-aside.
- The goal card uses icon actions in the upper right, a compact `$saved / $target` value with commas, and a progress bar. Remaining money appears only when the total is tapped. The header has Transactions and Settings icons. Activity is removed; purchases and savings adjustments join the Account transaction timeline. Past goals and the previous investing demo link remain under Goals.
- Apple Pay: a signed bundled GasFinder Log Purchase shortcut extracts Amount, Merchant and Currency Code. The import link validates USD and deduplicates repeat opens, then applies the active rule. The setup guide saves its step and opens the named shortcut on iOS 27, with earlier-iOS instructions. Apple still requires card/Transaction-trigger setup. Returning from Shortcuts starts checking, not a claim that automation is enabled; only a new shortcut import confirms receipt of a purchase. Actual Wallet taps need physical-phone testing.
- Account mirrors an account summary: **Available to spend = manually saved bank balance − money set aside** is the primary value. The actual balance is smaller and masked until tapped; editors open from round actions. Top safe-area spacing keeps the title below the phone status bar. One Import statement action remains on Account. Unified history includes bank movements, manual/Shortcut purchases and standalone savings adjustments. Purchase-related set-asides are shown inside their purchase detail. Expand a purchase for editing/deletion and savings suggestions/custom amounts/skipping; a Log a purchase form is also available. See all opens a virtualized list with search and money-in/money-out/pending/savings filters at `/account-transactions`; `/activity` redirects there. Savings adjustments do not appear as bank credits/debits. Imports never deduct from the saved balance again. Store version 5 and existing route/storage names are preserved.
- Bank PDF/CSV import: Account → Import statement, Transactions → Import, or Subs opens `/bank-import`. Citizens checking/savings text PDFs are parsed locally with bundled PDF.js in an Expo DOM component; unsupported/ambiguous rows are reported with page/line references. Scans, password-protected PDFs, credit cards and other banks are not supported yet. Choose a PDF or CSV, or paste CSV; for CSV review column mapping/date order/spending direction, select spending transactions, review possible matches and optionally apply the goal rule. Import retains purchase dates and source labels, caps set-asides, and deduplicates repeated/overlapping imports, including deleted imported records. Known credits, refunds, transfers and pending rows are excluded from savings purchases; non-USD rows are excluded throughout. The optional **Save bank history to Account** retains readable signed deposits/transfers/fees and supplied pending/posted status in a separate account ledger. Existing matching purchases appear once in Account. Previously imported PDFs can add this ledger without readding purchases; repeated ledger imports are disabled when unchanged. Raw files are not persisted or sent to a server. Account balances remain manually reported. Native file picking uses expo-document-picker and needs a rebuilt development app; pasting works in existing builds.
- Amazon product goals: Goals → Goal from Amazon link opens `/amazon-goal`. Explicit paste or Get product details retrieves the name, selected variant and full USD price from supported public Amazon pages, resolving a.co links. Native uses an incognito temporary WebView; web uses the Expo API route `/api/amazon-product` (deploy the server output for production web). Values remain editable and require confirmed creation. Blocked, unavailable, ambiguous or non-USD offers retain any readable name and offer retry/manual entry. Imported prices carry read timestamps and Amazon provenance; edited prices/variants become manual. Existing active-goal, archive and savings assignment rules remain. Images and the Safari helper remain planned. Live server access returned an Amazon service error; physical phone success still needs verification.
- Subs derives recurring-charge suggestions from confirmed bank imports, with supporting dates/amounts and editable name/price/cadence/renewal date before adding. Single known/explicitly recurring charges are marked possible; dismissals persist, and existing/renamed/canceled subscriptions are suppressed. Renewal dates are posting-date estimates. Subs supports monthly/yearly renewals, day-before review, local reminder notifications and cancellation notes. Spending Pause offers logging the actual bought amount once.
